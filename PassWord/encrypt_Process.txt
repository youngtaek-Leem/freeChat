Connect Vault - 암호화 프로세스 및 데이터베이스 분석 보고서
================================================================================

1. 마스터 비밀번호 관리 프로세스 (Zero-Knowledge 설계)
--------------------------------------------------------------------------------
Connect Vault는 사용자의 마스터 비밀번호를 절대 평문으로 저장하지 않는 영지식(Zero-Knowledge) 아키텍처를 따릅니다.

[A. 비밀번호 설정 및 변경 단계]
- 검증용 해시 생성: 입력된 비밀번호를 Argon2 알고리즘을 통해 해싱하여 'master_hash'로 저장합니다. 이는 로그인 시 비밀번호 일치 여부를 확인하는 용도로만 사용됩니다.
- 암호화 솔트 생성: 16바이트의 무작위 바이트열(Salt)을 생성하여 'master_salt'로 저장합니다. 이는 동일한 비밀번호라도 사용자마다 다른 암호화 키가 생성되도록 보장합니다.

[B. 금고 열기(인증) 단계]
- 1차 검증: 입력한 비밀번호를 저장된 'master_hash'와 비교하여 인증을 수행합니다.
- 키 유도(KDF): 인증 성공 시, '입력 비밀번호'와 'master_salt'를 PBKDF2-HMAC-SHA256 알고리즘에 통과시켜 32바이트의 대칭 암호화 키(Symmetric Key)를 생성합니다.
- 휘발성 저장: 생성된 키는 메모리에만 일시적으로 상주하며, DB나 파일로 절대 저장되지 않습니다.

[C. 데이터 암호화 및 복호화 단계]
- 암호화: AES-256 GCM 모드를 사용합니다. 매 저장 시마다 고유한 12바이트 Nonce를 생성하여 [Nonce + 암호문] 형태로 저장합니다.
- 복호화: 저장된 Nonce와 메모리 상의 유도 키를 사용하여 원래의 비밀번호를 복원합니다.

--------------------------------------------------------------------------------
2. vault.db 데이터베이스 분석 결과
--------------------------------------------------------------------------------
DB 파일 내의 데이터 저장 상태를 분석한 결과, 설계된 보안 원칙이 엄격히 준수되고 있음을 확인했습니다.

[테이블 1: config]
- master_salt: 무작위 바이트 데이터 (BLOB). 키 유도 시 사용.
- master_hash: Argon2로 해싱된 비밀번호 (BLOB). 인증 시 사용.
=> 분석: 마스터 비밀번호의 원문을 알 수 없는 상태로 안전하게 저장됨.

[테이블 2: vault]
- service / username: 평문 저장. (어떤 서비스의 계정인지 식별하는 용도)
- encrypted_password: [12바이트 Nonce] + [AES-256 GCM 암호문] (BLOB).
=> 분석: 실제 비밀번호는 읽을 수 없는 바이너리 형태로 저장되어 있으며, 마스터 키 없이는 복호화가 불가능함.

--------------------------------------------------------------------------------
3. 보안성 종합 평가
--------------------------------------------------------------------------------
- DB 탈취 시나리오: 공격자가 vault.db 파일을 획득하더라도, 마스터 비밀번호를 모르는 한 개별 계정의 비밀번호를 알아낼 수 없습니다.
- 무작위 대입 공격 방어: Argon2의 높은 연산 비용과 PBKDF2의 반복 횟수를 통해 Brute-force 공격에 대해 강력한 저항력을 가집니다.
- 무결성 보장: AES-GCM 모드를 통해 암호화된 데이터가 임의로 수정되었을 경우 복호화 단계에서 이를 감지하고 차단합니다.
